# Commission Album Catalog Design

## Goal

Replace album, service, and price fixtures with a Supabase-backed catalog. Admin can add, edit, order, publish, archive, and restore albums and their service types. Public commission pages read the same catalog and update after admin mutations.

## Scope

- Seed four real albums: Chibi, Illustration, VTuber, and Skin Minecraft.
- Preserve current approved public and admin visual layouts.
- Add a dedicated admin album editor page.
- Support localized Thai and English album/service content.
- Support service reference prices for Personal, Commercial, Normal, and Rush variants.
- Remove fixture fallback from album and service pages.
- Do not deploy or merge as part of this work.

## Data Model

### `commission_albums`

- UUID primary key
- unique stable `slug`
- localized `name` and `description` JSON
- optional cover asset reference
- availability: `open`, `limited`, or `closed`
- `published`, `display_order`, timestamps, and nullable `archived_at`

### `commission_services`

- UUID primary key and album foreign key
- unique slug within album
- localized name, description, and timing guidance
- availability, revision allowance, published state, display order, timestamps, and nullable `archived_at`

### `commission_service_prices`

- service foreign key
- usage: Personal or Commercial
- pace: Normal or Rush
- authoritative THB satang amount
- localized label and display order

Existing commission requests and quotes continue storing immutable service and price snapshots. Catalog edits affect only future requests.

## Access and Safety

- Anonymous users can read published, non-archived catalog rows only.
- Authenticated users receive the same public read boundary.
- Only the sole admin can mutate catalog rows through guarded server routes and database RPCs.
- Normal removal archives a row. Archive hides it publicly but keeps historical links.
- Permanent deletion is unavailable when dependent services, requests, quotes, or portfolio items exist.
- Audit log records create, update, archive, restore, and reorder actions.

## Admin UX

The existing Albums and Pricing page becomes live:

- Search, availability filter, and sort controls work.
- Add Album opens a create page.
- Edit Album opens `/admin/catalog/[albumId]`.
- Overflow menu archives or restores an album.
- Cards show live service count and status.
- Empty state shows an Add Album action instead of fixtures.

Album editor contains:

- Thai/English name and description
- slug, cover, availability, publish state, and display order
- service list with add, edit, reorder, archive, and restore
- per-service Personal/Commercial and Normal/Rush prices
- timing guidance and revision allowance

## Public UX and Data Flow

Public commission album and sub-album pages query Supabase on the server. Only published, non-archived rows render. Admin mutations revalidate affected Thai and English catalog routes. Missing or archived slugs return not found instead of fixture content.

## Media

Album and service cover records store an R2 object key and image metadata. Existing fixture art is not treated as catalog data. Until a real cover is uploaded, UI uses a neutral theme placeholder generated by CSS, not a fake portfolio image.

## Errors and Validation

- Slugs must be lowercase URL-safe and unique.
- Thai and English names are required.
- THB prices must be whole satang, non-negative, and within the existing quote money ceiling.
- Archive requires confirmation.
- Mutation conflicts and validation errors stay on the editor with Thai messages.
- Failed public catalog reads show a safe retry state; they never fall back to mock data.

## Verification

- Repository tests for public/admin visibility
- Route tests for admin authorization and validation
- Component tests for create, edit, archive, restore, search, filter, and empty states
- Public integration tests proving admin changes appear and archived rows disappear
